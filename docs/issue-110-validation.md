# #110 원문 텍스트 근거 강조

브랜치: `feature/fe/110-summary-evidence-highlight`
기준 커밋: `b9e328bb783bce6fadbc4a9df184bf4fe955b171`

## 구현
- 상세 view의 기존 `result` 컬럼을 조회한다. DB migration은 필요 없다.
- `text_matched` 검증과 `source_type=text`를 가진 근거만 현재 본문과 정확히 대조한다. 파일 참조, 제목에만 있는 구절, 중복 위치, 불일치 구절은 제외한다.
- 기존 백엔드 summary_highlights의 카드별 필드 대응을 따른다. 좌표는 현재 본문의 JavaScript UTF-16 기준으로 계산한다.
- 일반·편한 화면에서 카드를 선택하면 원문으로 전환하고 대응 구간만 배경을 강조한다. 재선택으로 해제, 다른 카드로 변경, 읽기 방식 변경과 공지 데이터 변경 시 강조를 해제한다.
- 카드에서 링크·첨부·다른 화면을 열지 않는다. 기존 공식 원문과 첨부 버튼은 유지한다.
- 사전 단어 메타데이터와 밑줄·클릭을 유지한다. 쉬운말에 원문 좌표를 적용하지 않는다.
- 기존 카드 색상·폰트·배치·아이콘은 유지한다. 본문 강조색만 추가했다. 자동 스크롤은 추가하지 않았다.

## 검증 (2026-10-10)
- 관련 Node 테스트 28개 통과: summaryEvidence, easyNoticeDetail, noticeApi, onboardingPreview.
- Expo ESLint 통과.
- 전체 Node 테스트는 마지막 전체 실행에서 93개 중 90개 통과, 기존 deadlineReminderRace 3개 실패. 이후 추가한 렌더링 회귀 테스트 1개도 관련 테스트 실행에서 통과했다.
- TypeScript 전체 검사는 `src/features/widget/todayNotice.ts`가 존재하지 않는 `fetchTodayNotice`를 import하여 실패한다.
- 수정 전 HEAD를 별도 폴더에 추출하여 같은 TypeScript 오류와 알림 테스트 3개 실패를 재현했다. 이슈 범위 밖 코드에는 수정하지 않았다.
- 실제 로컬 웹 앱에서 시연용 데이터로 강조, 사전 클릭, 쉬운말에서 원문 전환과 외부 이동 없음을 확인했다. 휴대폰과 운영 DB 연동 시연은 수행하지 않았다.
- #104/#105/#106은 별도 브랜치이므로 최종 통합 후 카드 가독성, 사전 조회, 재작성 쉬운말과의 브라우저 동작을 다시 확인해야 한다.

## 시연 확인 순서
1. 텍스트 근거가 있는 공지에서 각 카드를 누르고 원문 해당 구간만 강조되는지 확인한다.
2. 쉬운말에서 카드를 눌러 원문으로 전환되는지 확인한다.
3. 같은 카드 재선택, 다른 카드 선택, 공지 이동으로 강조가 해제/변경되는지 확인한다.
4. 강조된 사전 단어의 뜻풀이가 열리고, 공식 원문·첨부 버튼이 유지되는지 확인한다.
5. 파일 근거만 있는 공지, 중복 구절, 수정된 본문에서는 잘못된 강조나 외부 이동이 없는지 확인한다.
